# 民事名誉权答辩工作流

> **从拿到起诉状到提交答辩状的完整流程** — 以被告视角, 用 defame-shield 工具辅助。

## 适用场景

- 你/你当事人是**民事名誉权诉讼的被告**
- 已经收到法院送达的起诉状副本
- 需要在**15 日答辩期内**提交答辩状
- 想用 AI 辅助但又担心质量和可靠性

## 工作流概览

```
┌─────────────────┐
│  1. 拿到起诉状  │  Word/PDF/图片
└────────┬────────┘
         │ 转 markdown
         ▼
┌─────────────────┐
│  2. 拆解起诉状  │  dsh analyze-complaint
│     (4 维 + 评分) │  → complaint-analysis.json
└────────┬────────┘
         │
         ▼
┌─────────────────┐
│  3. 生成答辩状  │  dsh generate defense --from-analysis
│  (按反点逐条)   │  → defense-<时间戳>.md
└────────┬────────┘
         │
         ▼
┌─────────────────┐
│  4. 抗辩自检    │  dsh self-check
│  (找漏洞 + 评分) │  → 评分 + 漏洞清单
└────────┬────────┘
         │
         ▼
┌─────────────────┐
│  5. 律师润色    │  人工补充 [待补充] 占位符
│  + 补证据      │  添加案件特有事实
└────────┬────────┘
         │
         ▼
┌─────────────────┐
│  6. 提交法院    │  打印签字 + 副本份数
└─────────────────┘
```

## Step 1: 拿到起诉状 → 转 markdown

工具**只支持 markdown** 输入。Word/PDF/图片需要先用其他工具转。

**转换方法**:
- **Word(.docx)**: 另存为 / 用 pandoc (`pandoc complaint.docx -o complaint.md`)
- **PDF**: 用 `pdftotext` / 微信文件传输助手的"提取文字"功能 / Adobe Acrobat
- **图片**: 用 OCR 工具 (微信/QQ/百度网盘都自带) 提取文字, 手工校对

转完后存到: `data/cases/<你的案件id>/complaint.md`

## Step 2: 创建被告案件

被告视角的案件,被告信息是你这边的人:

```bash
dsh case new my-def-001
```

交互式填写, **被告信息是你这边的当事人** (也就是你/你客户), 原告信息是起诉你的对方。

## Step 3: 拆解起诉状

```bash
dsh analyze-complaint data/cases/my-def-001/complaint.md \
  --case my-def-001 \
  --draft
```

- `--draft` 纯模板, 不用 API key
- 不加 `--draft` 走 AI (需 DEEPSEEK_API_KEY 或 MINIMAX_API_KEY)
- 输出: `data/cases/my-def-001/complaint-analysis.json`

**拆解结果包含 4 维**:
- 主体 (原告/被告/律师)
- 诉请 (5-10 条, 含金额)
- 事实 (侵权方式/内容/传播范围/时间)
- 法律依据 (民法典 1024/1025/1183 等)

外加 4 要件评分 (factAuthenticity / directedness / fault / damage) — 用于反点选择。

## Step 4: 生成答辩状 (基于拆解)

```bash
dsh generate defense --case my-def-001 \
  --from-analysis data/cases/my-def-001/complaint-analysis.json \
  --draft
```

输出: `data/cases/my-def-001/outputs/defense-<时间戳>.md`

**答辩状包含**:
1. ✅ 主体信息 (被告/原告)
2. ✅ 总体答辩策略 (杀伤力排序的 3 个反点)
3. ✅ 逐条诉请反驳 (每条匹配最适反点 + 引用法条)
4. ✅ 事实与理由 (被告视角, 显式标注 [待补充])
5. ✅ 类案参考 (裁判要点式, 不编案号)
6. ✅ 答辩证据指引 (按反点列出需补充的证据)
7. ✅ ⚠️ 重要提示 + 法律免责声明

**8 个反点自动选**:

| # | 反点 | 杀伤力 | 适用场景 |
|---|---|---|---|
| 1 | 事实基本属实 / 舆论监督免责 | 中 | 被告所述有合理来源/已尽核实义务 |
| 2 | 未实施被诉行为 | 中 | 账号非被告/内容非被告发布 |
| 3 | 未达名誉权侵害程度 | 中 | 未指名/不能识别/属合理评论 |
| 4 | 无损害后果 | 中 | 未举证财产/精神损害 |
| 5 | 无因果关系 | 中 | 损害系他因 |
| **6** | **超过诉讼时效** | **一票否决** | 侵权超过 3 年 |
| **7** | **管辖异议** | **一票否决** | 受案法院无管辖权 |
| **8** | **被告主体不适格** | **一票否决** | 被告非适格主体 |

## Step 5: 抗辩自检 (找漏洞)

```bash
dsh self-check data/cases/my-def-001/outputs/defense-*.md \
  --analysis data/cases/my-def-001/complaint-analysis.json \
  --severe-only
```

**输出**:
- 整体评分 0-100
- 漏洞列表 (按风险等级排序)
- 每个漏洞: 攻击方向 / 原告论据 / 修补建议 / 法条

**自检发现的常见漏洞**:
- 🔴 **CRITICAL**: 答辩状含 [待补充] 占位符 (AI 没填的事实)
- 🔴 **CRITICAL**: 程序性反点 (时效/管辖/主体) 适用但未采用
- 🟠 **HIGH**: 诉请未逐条回应
- 🟠 **HIGH**: 选择"事实属实"反点但缺核实义务证据
- 🟡 **MEDIUM**: 答辩状过短 / 法律引用过少 / 无证据清单
- ⚪ **LOW**: 无类案参考

## Step 6: 律师人工润色

**这一步是必须的, AI 不能替代**。

### 6.1 填充 [待补充] 占位符

所有 `[xxx]` 形式的占位符都要填写案件特有事实:

```markdown
### 二、答辩人的事实主张
[待补充: 答辩人需要在此节陈述自身的客观事实, 包括:
1. 被告的真实身份/职业/与原告的关系
2. 涉案内容的真实来源/性质
3. 被告未实施被诉行为的事实依据
4. 即使存在部分用词, 也是基于合理事由

重要: 此节内容需要根据案件实际情况填写, 切勿虚构。]
```

改成:

```markdown
### 二、答辩人的事实主张

1. **被告身份**: 答辩人系某科技公司 CTO, 与原告曾在 2022 年有过业务合作;
2. **内容来源**: 涉案微博内容来源于 [具体报道/采访/文件], 该 [报道/文件] 已公开发表;
3. **核实经过**: 答辩人发布前已与原告方 [某总] 当面核实过核心事实;
4. **合理事由**: 即使部分用词稍显尖锐, 亦系基于对行业乱象的合理批评, 属正当评论。
```

### 6.2 补充证据清单

按 [答辩证据指引] 章节的清单, 准备:
- 涉案账号注册信息
- 信息来源的原始材料
- 公证书 / 电子证据
- 证人证言
- 专家意见书

### 6.3 检查法律引用

- 答辩状引用的法条编号要核实 (AI 偶有编造)
- 与起诉状引用的法条逐一对照, 区分"同意/反对/另有解释"

### 6.4 调整反点选择 (必要时)

如果律师认为 AI 选的反点不合适, 可以:
1. 编辑 `data/cases/my-def-001/complaint-analysis.json` 调整 4 要件评分
2. 重新 `dsh generate defense` 生成

## Step 7: 提交法院

按答辩状末尾"附"章节准备:
- 副本份数 (= 原告人数)
- 答辩证据目录及全部证据材料
- 答辩人身份证明
- 授权委托书 (如委托律师)

**提交方式**:
- 直接交法院立案庭
- 通过 EMS 邮政特快专递 (保留底单)
- 通过电子诉讼平台 (部分法院支持)

## 实战经验

### 什么情况下 AI 生成质量高?

- ✅ 起诉状结构标准 (有清晰的"诉讼请求"/"事实与理由"/"法律依据")
- ✅ 事实部分含具体时间/地点/平台/数据
- ✅ 诉请不超过 8 条
- ✅ 案由明确 (网络侵权/传统媒体)

### 什么情况下需要人工介入更多?

- ⚠️ 起诉状格式不规范 / 内容凌乱
- ⚠️ 诉请超过 10 条
- ⚠️ 涉及多被告/多平台/复杂时间线
- ⚠️ 涉及刑事自诉交叉

### 答辩状提交后

1. 等待法院送达对方副本
2. 准备开庭 (提交证据原件/准备质证意见)
3. 庭审中坚持答辩状立场, 必要时当庭补充
4. 收到判决后, 评估是否上诉

## 法律声明再次强调

**本工具生成的所有内容均不构成律师法律意见**。

- 重大/复杂案件请委托执业律师
- 答辩状必须由律师审核签字
- 用户对事实真实性负全责
- LLM 输出需用户自行核实
